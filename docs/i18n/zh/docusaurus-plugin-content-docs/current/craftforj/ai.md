craftforJ 内置了一个完整的编码代理，可在你的**运行中的应用**内工作。它可以自由编写 Java，在你看到代码之前先编译自己写的内容，应用更改，并在应用重启后继续工作。它所做的一切，都是针对你眼前实际运行的应用，而不是基于对你代码仓库的猜测。

<VideoPlayer video="craftforj/ai-conversation" width={1920} height={1000} title="AI conversation" />

:::warning AI 仍可能出错
针对运行中的应用开展工作并编译自己的输出，让代理比盲目编写代码的代理准确得多。但它仍可能出错。请先检查它的操作，再决定是否保留。
:::

## 它会编写 Java {#it-writes-java}

代理不局限于你可以手动进行的属性更改。描述一个问题，它就会编写相应代码，根据任务需要添加方法、更改逻辑并重构视图。

它编写的每项编辑都会暂存，而不会直接写入磁盘。暂存的编辑会直接交由真正的 Java 编译器处理，代理会读取编译器返回的诊断信息，并在更改提交给你查看之前修正自己的错误。进入审核环节的代码，已经能够针对你运行中的应用成功编译。

完整验证需要 JDK。如果使用 JRE，craftforJ 会改为解析代码，并将编辑标记为未经验证，同时要求代理明确说明这一点，而不是声称代码已通过检查。

应用更改会重启你的应用。代理会等待重启完成，重新连接，并从中断处继续执行计划，因此跨越多次编辑和重启的任务也能顺利完成。

## 它会分步工作 {#it-works-in-steps}

你给代理的是一个目标，而不是一条命令。它会进行规划、检查所需内容、采取行动、检查结果并自我纠正；一轮对话中可以连续执行多个步骤，无需你逐步指挥。每个步骤都会在执行时显示在对话记录中，你可以展开任一步骤，查看代理具体调用了什么，以及返回了什么。

## 它可以访问的内容 {#what-it-can-reach}

代理拥有一套丰富的工具，涵盖 craftforJ 所了解的应用信息，包括：

- **你的组件** - 实时组件树、实际属性值，以及构建每个组件的 Java 代码。它可以更改属性、移除组件，并在页面上高亮显示组件。
- **你的源代码** - 读取项目根目录下的任意文件、暂存编辑、显示差异并应用更改。
- **你的路由** - 路由表、当前活动路由、导航到任意位置，以及更改路由上声明的访问规则。
- **你的主题和样式** - 读取和设置设计令牌、保存主题，以及搜索可用字体和图标。
- **页面本身** - 针对实时页面注入 CSS 和 JavaScript，并截取组件的屏幕截图供其查看。
- **webforJ 知识库** - 与 [webforJ MCP server](/docs/ai-tooling/mcp) 提供给编辑器的文档、组件样式接口和 `--dwc-*` 令牌工具相同。这些功能内置其中，始终可用。

由于代理通过 craftforJ 访问所有这些内容，它掌握的信息与你相同。它读取的是实际值，而不是源代码所暗示的值。

## 审批 {#approvals}

你可以预先决定代理能自主执行多少操作：

- **执行前询问** - 每项会产生实际影响的操作都会暂停，等待你批准。
- **自动应用编辑** - 代理可以自由工作，但在移除内容或运行脚本之前仍会征求同意。
- **自主运行** - 代理工作时不会暂停。

代理征求同意时，请求会连同它想执行的操作一起显示在对话记录中，你可以仅允许这一次，也可以允许本次对话中的后续操作。

![助手在对话记录中内嵌询问是否可以执行操作](/img/craftforj/ai/approval-prompt.png#rounded-border)

如果你刚开始使用代理，可以先让它每次都征求同意。观察它的工作方式之后，再允许它自行应用编辑，这样既能减少大多数中断，也能让重要决定继续由你掌控。

## 在对话中与应用协作 {#working-with-the-app-in-a-conversation}

代理会在需要时读取所需内容，而不是一开始就拿到整个应用；craftforJ 会向你展示附加到对话中的内容。你可以直接从组件树中将组件交给它，也可以在对话进行时从页面上选取组件。如果你想询问某个元素的外观，代理可以截取组件的屏幕截图。这需要使用支持图像的模型。

:::warning 屏幕截图会包含屏幕上的所有内容
屏幕截图会包含应用当时正在显示的任何数据。在将运行真实数据的应用连接到托管模型之前，请考虑这一点。
:::

## 配置模型 {#configuring-a-model}

craftforJ 不附带自有模型，因此由你选择驱动它的模型。添加一个受支持提供商的 API 密钥，或将 craftforJ 指向本地运行的模型。你的密钥会存储在运行应用的机器上，助手只会在页面打开期间将其保存在内存中，绝不会存储在浏览器存储中。它会直接从浏览器与所选提供商通信，不经过你的服务器，也不会与其他任何人通信。

模型选择器会显示不同模型的特点，包括模型一次可以处理多少应用和对话内容、一次对话的成本，以及模型是否支持图像或会在回答前进行推理。不能调用工具的模型可以参与对话，但无法检查或更改任何内容。

![模型选择器展示可用模型之间的区别](/img/craftforj/ai/model-picker.png#rounded-border)

在本地运行模型可以确保所有内容都留在你的机器上。本地模型通常默认使用较小的上下文窗口，而讨论真实应用的对话很快就会填满它，因此请尽可能为模型提供机器能够承载的最大上下文。

## 对话 {#conversations}

对话按应用分别保存；如果问题涉及你之前完成的工作，代理可以回顾较早的对话。当对话超出模型的上下文容量时，craftforJ 会总结较早的消息，让工作得以继续，而不是失败，并会在聊天中说明这一点。

当工作超出 craftforJ 的能力范围时，你可以总结对话，并将其交给编辑器的助手。安装了 [webforJ AI 插件](/docs/ai-tooling)后，该助手就能更准确地接手工作。

## 关闭功能 {#turning-it-off}

[`ai.enabled`](/docs/craftforj/configuration#feature-flags) 属性会从 craftforJ 中完全移除助手。`[`ai.freeform-changes`](/docs/craftforj/configuration#feature-flags) 属性会保留助手，但阻止它自行编写 Java。
